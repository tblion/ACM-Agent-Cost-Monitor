# Application i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Internationaliser toute l'interface en français et en anglais, détecter la langue système sans préférence persistée, permettre le choix dans Réglages, et imposer la parité des traductions pour les évolutions futures.

**Architecture:** Ajouter une instance i18next fournie à React par `I18nextProvider`, avec deux ressources statiques et une liste de langues supportées. Les réglages Tauri portent une préférence `language` nullable ; `null` déclenche la détection système et l'anglais est le repli. Les composants utilisent `useTranslation`, tandis que les nombres et dates passent par des helpers `Intl` dépendant de la locale active.

**Tech Stack:** React 19, TypeScript strict, `i18next`, `react-i18next`, Tauri 2/Rust/Serde, Vitest, validation Chrome/MCP.

- [ ] **Step 1: Ajouter les dépendances runtime**


- [ ] **Step 2: Définir les langues et la détection**

Créer `src/i18n/locale.ts` avec les types et fonctions suivants :

```ts
export const supportedLanguages = ["fr", "en"] as const;
export type SupportedLanguage = typeof supportedLanguages[number];

export function normalizeLanguage(value: string | null | undefined): SupportedLanguage {
  return value?.toLowerCase().startsWith("fr") ? "fr" : "en";
}

export function detectSystemLanguage(): SupportedLanguage {
  return normalizeLanguage(typeof navigator === "undefined" ? undefined : navigator.language);
}

export function languageLocale(language: SupportedLanguage): string {
  return language === "fr" ? "fr-FR" : "en-US";
}
```

La fonction doit traiter `fr-CA` comme français et toute autre valeur comme anglais.

- [ ] **Step 3: Créer les ressources i18next**

Créer `src/i18n/resources.ts` avec un objet `resources` contenant les namespaces `translation` pour `fr` et `en`. Commencer par les clés structurées par surface (`app`, `header`, `filters`, `kpi`, `charts`, `sessionTable`, `settings`, `rates`, `common`, `accessibility`) et y mettre toutes les chaînes déjà recensées dans les composants existants, y compris les tooltips et erreurs.

Déclarer les ressources françaises comme source de type et typer les ressources anglaises avec le même shape afin qu'une clé manquante échoue à la compilation.

- [ ] **Step 4: Configurer i18next et React**

Créer `src/i18n/config.ts` :

```ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import { resources } from "./resources";

void i18n.use(initReactI18next).init({
  resources,
  lng: "en",
  fallbackLng: "en",
  supportedLngs: ["fr", "en"],
  defaultNS: "translation",
  interpolation: { escapeValue: false },
  returnNull: false,
});

export default i18n;
```

Importer cette instance dans `src/main.tsx` et envelopper `<App />` dans `<I18nextProvider i18n={i18n}>`.

- [ ] **Step 5: Ajouter les helpers de formatage**

Créer `src/i18n/format.ts` avec `formatNumber(value, language, options?)`, `formatCurrency(value, language)`, `formatDate(timestamp, language)` et `formatCompactTokens(value, language)`. Chaque helper doit appeler `languageLocale(language)` et ne doit contenir aucun texte traduit. Les options doivent préserver les règles d'affichage actuelles : montants avec au plus deux décimales, dates locales, tokens compacts avec unité localisée via le catalogue.

- [ ] **Step 6: Écrire les tests de socle**

Dans `src/i18n/resources.test.ts`, tester `normalizeLanguage`, `detectSystemLanguage` avec un mock de `navigator.language`, les formats `fr-FR`/`en-US`, et la parité récursive des clés des deux ressources. Le test de parité doit comparer les chemins feuilles et échouer avec le chemin précis d'une clé absente.

```bash
npm run build
```

Attendu : tests et build passent avant toute migration de composant.


### Task 2: Persister la préférence de langue dans les réglages

**Files:**
- Modify: `src/types.ts`
- Modify: `src-tauri/src/model.rs`
- Modify: `src-tauri/src/settings.rs`
- Modify: `src/App.tsx`
- Modify: `src/components/SettingsModal.tsx`
- Modify: `src/i18n/locale.ts`
- Modify: `src/i18n/config.ts`

- [ ] **Step 1: Étendre les types**

Ajouter `language: SupportedLanguage | null` dans le type TypeScript `Settings` et `language: Option<String>` dans le struct Rust `Settings`. Ajouter `#[serde(default)]` au champ Rust ou conserver le `default` de la structure pour que les anciens `settings.json` chargent avec `None`. Le `Default` Rust doit définir `language: None`.

- [ ] **Step 2: Ajouter le test de compatibilité des réglages**

Étendre le test Rust `roundtrip` pour vérifier la sauvegarde et le chargement d'une langue explicite. Ajouter un test qui désérialise un JSON existant sans `language` et vérifie que la valeur est `None`.

- [ ] **Step 3: Centraliser le choix de langue effectif**

Ajouter dans `src/i18n/locale.ts` une fonction `resolveLanguage(preference: string | null | undefined): SupportedLanguage` qui utilise la préférence si elle vaut `fr` ou `en`, sinon `detectSystemLanguage()`. Toute préférence inconnue doit être traitée comme absente et donc suivre le système.

- [ ] **Step 4: Initialiser la langue après chargement des réglages**

Dans l'effet de chargement des réglages de `App.tsx`, appeler `resolveLanguage(s.language)`, puis `await i18n.changeLanguage(language)` avant `setSettings(s)`. Synchroniser `document.documentElement.lang` dans un effet dépendant de `i18n.language`, avec `fr` ou `en` comme valeur normalisée.

- [ ] **Step 5: Ajouter le select natif dans Réglages**

Dans `SettingsModal.tsx`, ajouter une copie locale `language` via le même mécanisme que les autres champs :

```tsx
<label htmlFor="language-select">{t("settings.language.label")}</label>
<select
  id="language-select"
  value={s.language ?? "system"}
  onChange={event => set({ language: event.target.value === "system" ? null : event.target.value as SupportedLanguage })}
>
  <option value="system">{t("settings.language.system")}</option>
  <option value="fr">🇫🇷 Français</option>
  <option value="en">🇬🇧 English</option>
</select>
```

Le choix `system` doit être visible pour conserver le comportement de détection automatique, même si la langue affichée courante est française ou anglaise.

- [ ] **Step 6: Appliquer uniquement après Enregistrer**

Modifier `saveSettingsAndClose` dans `App.tsx` pour sauvegarder d'abord `s`, puis appeler `i18n.changeLanguage(resolveLanguage(s.language))`. Ne pas appeler `changeLanguage` dans `SettingsModal` pendant la sélection. La fermeture par Annuler doit simplement démonter la modale.

- [ ] **Step 7: Vérifier les réglages**

```bash
npm test -- src/i18n/resources.test.ts
cd src-tauri && cargo test settings
```

Attendu : les anciens réglages restent lisibles et une préférence explicite est persistée.

```bash
git add src/types.ts src-tauri/src/model.rs src-tauri/src/settings.rs src/App.tsx src/components/SettingsModal.tsx src/i18n
git commit -m "feat: persist interface language"
```
